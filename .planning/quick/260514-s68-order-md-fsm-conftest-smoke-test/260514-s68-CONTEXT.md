<decisions>
## Implementation Decisions

### Smoke 구조 — 이원화

**FSM transition smoke + custom0 entry smoke**:

- `test_fsm_smoke.py` 는 `fsm.NpuState` enum + `state_decode/state_dispatch/
  state_execute/state_writeback`의 transition 시퀀스 `IDLE → DECODE → DISPATCH
  → EXECUTE → WRITEBACK → IDLE` 임포트 존재 검증 + 한 cycle 직접 호출 (mock
  context dict 주입) 후 next state 값 검증.
- `test_custom0_smoke.py` 는 real `GtxNpu` 인스턴스에 `MockProcessor` + 더미
  `rocc_insn_t`를 넘겨 `custom0()` 한 번 호출 → return value 가 int 인지만 확인.
  실제 dispatch 결과 정합성은 후속 회귀가 책임.

이 둘이 같이 PASS 하면 "구조적으로 시뮬레이터가 살아있다"의 최소 신호.
ORDER.md의 INIT 단계는 `GtxNpu.__init__/_apply_vendor_defaults`로 흡수되므로
별도 transition state 가 없음 — fixture 가 곧 INIT 검증을 겸함.

### GtxNpu fixture — real GtxNpu + MockProcessor minimal

`@isa.register("gtx")` 의 실제 인스턴스화. d6f73f9 의 Tensor-backed
`RegisterFile` + CUDA 메모리 계층이 실제로 build 되는지 검증해야 의미 있음.

`MockProcessor` 는 다음 surface 만 제공:

- `state.XPR[idx]` (`__getitem__` returns int) — handlers 가 `proc.state.XPR[insn.rs1]`
  형태로 읽음.
- `state.XPR.write(idx, val)` — `GtxNpu.reset()` 의 sp 초기화 호출 경로.
- `get_csr(addr) -> int`, `set_csr(addr, val)` — `reset()` 안의 `mstatus.FS`
  설정 경로. `Exception` 던져도 됨 (`reset()` 이 `try/except Exception: pass` 로
  감쌈).
- `get_state()` — 옵션. 필요 시 self return.

mock 의존성은 **이 3-4 메서드로 한정**. `_riscv.so` import 는 시도하지 않음
(import 가능하면 GtxNpu 정상 build, 불가능하면 fixture 가 명확한 에러로 fail).

### CUDA 정책 — 필수 (skip 없음)

`torch.cuda.is_available() == False` 면 모든 GTX 테스트 collection 단계에서
**명확한 에러로 fail**. conftest 최상단에 단언:

```python
if not torch.cuda.is_available():
    pytest.exit("GTX tests require CUDA — ORDER.md constraint", returncode=1)
```

ORDER.md "DDR은 CPU, 나머지 메모리 계층은 반드시 cuda" 가 단순한 best-practice
가 아니라 설계 invariant 임. CPU fallback 을 conftest 에서 허용하면 누군가
ORDER.md 와 어긋난 코드를 실수로 land 할 수 있음. CI runner 정책은 별도 결정
(현재 cibuildwheel matrix 가 GPU 가 없으면 이 conftest 가 explicit fail 시킬 것).

### Regression seed — smoke 밖 (별도 파일 미래 작업)

smoke 셋에는 vendor `.elf` 또는 fake firmware 시퀀스 모두 **포함 안 함**.

- 이유 1: smoke 가 PASS 하면 곧 dispatch chain 이 살아있다는 신호. 그게 충분.
- 이유 2: `.elf` 회귀는 실패 시 원인이 multi-tile DMA / FP16 정밀도 / vendor
  encoding gap 등 너무 다양해서 smoke 신호를 흐림.
- 이유 3: vendor `.elf` 가 없는 CI 머신에서 smoke 자체가 skip 으로 떨어지는
  것을 피하고 싶음.

후속 quick task 가 `test_regression_seed.py` 로 ABS 1 op 회귀 1개를 추가.

### Claude's Discretion

- conftest fixture 이름 (`gtx_npu`, `mock_proc`, `dummy_insn` 권장)
- `MockProcessor` 클래스 위치 (`tests/gtx/_mocks.py` 새로 작성, 기존 38개 중
  `_mocks.py` 가 삭제되었으므로 같은 경로에 재생성)
- `pytest.fixture` scope (function 권장 — state leak 방지)
- 더미 `rocc_insn_t` 생성 방식 — `riscv.disasm.disasm_insn_t` 또는 NamedTuple
  fallback 중 import 가능한 것 사용 (기존 `disasm.py:_PyDisasmInsn` 패턴 참고)

## Specific Ideas

- d6f73f9 npu.py:99 `@isa.register("gtx") class GtxNpu(isa.ROCC)` — fixture
  에서 직접 인스턴스화하면 됨. `__init__` 에서 `mem.load_via_env()` 가
  `GTX_DDR_LOAD` env var 가 없으면 no-op 이므로 fixture 에서 env clear 필요.
- d6f73f9 npu.py:166 `_atexit.register(self.mem.dump_via_env)` — 테스트 종료
  시 spurious DDR dump 를 피하려면 `GTX_DDR_DUMP` env clear 도 fixture 에서.
- fsm.py 5.1K — `run_pipeline(npu, kind, proc, insn, xs1, xs2)` 가 entry,
  내부에서 `state_decode → state_dispatch → state_execute → state_writeback`
  순으로 4 direct call (f50a292 후). smoke 는 이 4개 함수의 존재만 확인하고
  signature 가 `state_xxx(npu) -> NpuState` 인지 검증.
- writeback.py 는 R1 cleanup 후 `return NpuState.IDLE` 한 줄 — smoke 가 이걸
  검증.
- ORDER.md 의 C1/C2/C3/C4 context 표는 현재 dispatch 에 영향 없음
  (모든 핸들러 universal). smoke 에서 context transition 은 테스트하지 않음.
