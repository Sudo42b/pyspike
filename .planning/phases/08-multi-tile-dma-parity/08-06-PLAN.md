## Contract 1 — BE FP16 vs LE FP16 byte-order boundary

The NPU + DDR HW model represents FP16 values in two byte orders depending on
the data source:

- **LE FP16 (pyspike default)** — `np.float16.view(np.uint8)` produces
  `[low_byte, high_byte]`. Pure-Python NumPy backend matches the host's
  little-endian byte order. All P3/P4/P5/P6 hand-built tests use this.
- **BE FP16 (vendor reference)** — vendor `_ref.txt` golden files store
  FP16 values as `high_byte low_byte`. This matches the SystemC HW
  simulation that produced the vendor goldens. See
  `vendor/gtx_cpp_reference/gtx/CLAUDE.md` "FP16 byte order" for the
  authoritative vendor specification.

Quoting `vendor/gtx_cpp_reference/gtx/CLAUDE.md`:

> [Insert the exact "FP16 byte order" paragraph from
>  vendor/gtx_cpp_reference/gtx/CLAUDE.md verbatim here. Executor reads
>  that file at task time and copies the relevant paragraph(s).]

When pyspike loads / dumps a vendor-derived `.elf`, the
`GTX_DDR_REVERSED=1` env var flips the parser direction so that BE
goldens compare byte-exact against pyspike's LE-default output.

## Contract 4 — `_find_elf` search priority

`tests/gtx/test_regression_fw_full_sweep.py:_find_elf` resolves an op's
`.elf` in this order (D-05):

1. `tests/gtx/data/firmware/<elf_stem>.elf`        (P5/P6 hand-built — wheel-bundled)
2. `tests/gtx/data/elf/<elf_stem>.elf`             (P5/P6 legacy location)
3. `${GTX_VENDOR_TEST_DIR}/<OP_DIR>/n1s16/n1s16_<elf_stem>.elf`
                                                    (D-13 default = `/mnt/e/14_NIGHTLY/pyspike/test/`)

**Precedence rule**: hand-built always wins on collision. New ops with no
hand-built `.elf` (e.g., NEG, EXP) hit candidate 3 and use the vendor
pre-built. P5/P6 ops with hand-built `.elf` (RELU, GELU, ABS, ...) are
unaffected by the vendor-path addition.

**Override**: setting `GTX_VENDOR_TEST_DIR=/some/other/path` redirects
candidate 3 only. Candidates 1 and 2 are repo-relative and unaffected.

```markdown
### FP16 byte-order boundary (BE vs LE)

The pyspike GTX NPU operates in **LE FP16** byte order natively (matching
host x86_64 little-endian + `np.float16.view(np.uint8)` semantics). Vendor
HW simulation (SystemC) produces **BE FP16** in `_ref.txt` golden files.

The boundary is mediated by `GTX_DDR_REVERSED=1` env var, read by
`src/main/python/riscv/gtx/ddr.py` at `ddr_init_from_file` and
`ddr_dump_to_file` entry points. When set, both functions reverse byte
ordering on read/write so that vendor BE golden files compare byte-exact
against pyspike's LE-default in-memory representation.

The regression sweep harness
(`tests/gtx/test_regression_fw_full_sweep.py`) auto-applies
`GTX_DDR_REVERSED=1` for vendor-rooted `.elf` paths only (D-10 inline
subprocess env, NOT autouse fixture). See
`tests/gtx/data/firmware/README.md` Contracts 1 & 2 for the canonical
documentation.

Production code (`riscv.gtx.*`) sees only LE FP16; the BE/LE conversion
is fully encapsulated in the DDR I/O layer.
```
